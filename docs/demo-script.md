# 5 分鐘 Demo／簡報講稿

> 畫面對照：研究首頁 →「研究摘要」分頁 →「互動圖表」分頁 →「執行流程」分頁 → `/backtest` 回測頁。
> 每段標題後的括號標示該段應該停在哪個畫面。

## 0:00–0:35 問題（首頁）

加密貨幣研究通常要手動查價格、新聞、社群與鏈上資料，而且查完之後，**沒有人說得清楚每個結論是從哪一筆資料來的**。
我們的 Agent 團隊把這條流程整合起來，並且讓每一句話都可以點回原始來源。

## 0:35–1:10 解法（首頁，指著功能標籤）

使用者輸入幣種與問題後，流程分成三個階段、各有獨立時間上限：**蒐集 7 分鐘 → 整理與報告 3 分鐘 → 稽核 2 分鐘**。
蒐集階段由 6 個領域 Agent（新聞／社群／市場／技術衍生品／鏈上／總經）**同時執行**，共涵蓋 11 個資料來源，
新聞面還會爬取文章全文。上限只是天花板 —— 每個階段做完就立刻進入下一階段，實測整趟約 6 秒。
單一來源失敗只會降級，不會中斷。

## 1:10–2:10 結論先行（研究摘要分頁）

輸入 ETH 與研究問題，等待約 30–60 秒。報告以固定順序呈現：
**結論 → 已確認事實 → 推論 → 反方證據 → 信心與限制 → 資料來源 → 獨立稽核**。

四個要講的點：

1. **立場標籤**：最上方的「偏多／中性／偏空」不是模型自由生成，而是由證據訊號加權計算 ——
   方向性權重需達 1.5、單邊淨優勢需超過 25% 才會給方向，否則一律中性。展開「這個立場是怎麼算出來的？」
   可以看到每一項推力與其 evidence ID。**同一批證據永遠得到同一個立場，離線模式也一樣。**
2. **腳註可追溯**：事實與推論句尾的上標數字，對應第 6 節的來源清單，點下去直接連到原網站。
3. **主動列反證**：第 4 節「反方證據」是系統從本次訊號中自動挑出反向的那一側，不是模型客套話。
4. **獨立稽核**：第 7 節是另一個 agent 的第二次獨立呼叫，任務是**攻擊前面的分析** —— 檢查結論有沒有超過證據、
   反證有沒有被忽略、信心是否相稱。它**只能標註問題與下調信心，不能改寫結論**；會改寫的稽核等於第二個分析師，
   讀者就失去了獨立檢查。稽核若引用不存在的 evidence ID，整份稽核會被丟棄。

## 2:10–3:00 互動圖表（互動圖表分頁）

滑鼠移到任一張圖上，即時顯示該點數值。這裡有兩個評審通常會追問的東西：

- **長期價格脈絡**：其他來源都是 14 天窗口，這張表用 5 年日線回答「這個波動以這個幣自己的標準算大還算小」。
  Demo 時直接指出對比 —— 近 14 天是正報酬，但近 1 年 -50%、目前價格位於一年區間的第 9 分位。
  **只看 14 天會得到相反的印象。**
- **鏈上鎖倉量（TVL）**：價格是市場預期，TVL 是真正鎖進鏈上的資金。當兩者背離（例如價格 90 天 -19%、
  但 TVL 30 天 +12.7%），這個背離本身就是訊號。

消息面已升級為 AI 中文重點整理，來源以上標標在段落末尾。素材分三級：白名單網域（Cointelegraph、Decrypt）
會抓取全文，其餘只有導言或標題。**要主動說明限制**：Google News 的連結是 JS 跳轉頁且其 robots.txt 全站禁止，
所以那部分永遠停在標題層級 —— 我們每次抓取前都會檢查 robots.txt。

## 3:00–3:40 可靠性與 fallback（執行流程分頁）

這一頁是「多 agent 平行」最直接的證據：**三階段預算表**顯示每階段的上限、實際耗時與用掉比例
（實測只用掉不到 1%）；**平行 Agent 表**顯示 6 個 agent 各自的耗時與負責來源，總耗時等於最慢的那一個，
而不是所有來源的加總（序列 7.0 秒 → 平行 3.0 秒）。下方是每個來源的成功／降級狀態與 watchdog 紀錄。

**演一次失敗情境**：切換到 `demo-fixtures/` 的固定輸出，說明 API 全掛或 LLM 配額用盡時，
系統會退到確定性推理，報告照樣產出、證據照樣可追溯，執行記錄會誠實標成 `offline_fallback`。

## 3:40–4:25 策略回測（`/backtest` 頁面）

從首頁下方進入回測頁。用 5 年日線逐根重放 Vegas 通道 + RSI 的進出場規則，與買進持有並列比較。

**這一段的重點是誠實，不是績效**：

- 開場就講限制：整個測試區間只產生 1–3 筆交易，**樣本數不足以證明策略有效**，任何勝率都只是觀察。
- 逐根重放讓前視偏誤在結構上不可能發生 —— 每一步只把「到當天為止」的 K 棒餵給策略函式。
- 已扣手續費 0.1%／邊；上方可切換五個幣種，看規則在其他標的上是否一致。
- 結論講法：「我們沒有宣稱這個策略會賺錢。我們展示的是它在歷史資料上實際會怎麼進出場，以及我們如何驗證它。」

## 4:25–5:00 團隊分工、限制與下一步

Data Engineer 負責 11 個資料 adapter，Agent Engineer 負責 Orchestrator 與時間預算，
Research Analyst 負責策略與指標，Product QA 負責 UI 與 117 個測試，PM 負責整合與交付。

已知限制：全文抓取僅涵蓋兩個白名單網域，其餘來源仍是導言或標題層級；巨鯨追蹤僅支援 BTC/ETH/BNB；
回測的時間框架與線上運行不同（日線 vs 4H/1H）；每次分析消耗 3 次 LLM 呼叫，免費配額每日僅約 6 次。
下一步：在真實配額下驗證 Critic 的 API 往返、回測參數穩健性檢驗、全文白名單擴充。
